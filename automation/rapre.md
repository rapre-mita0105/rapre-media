# Rapre Instagram 自動投稿 手順書

この手順書は、無人の定期実行が毎回読み、次の投稿枠1回分を生成・予約するためのものです。
（2026-10-13改定：紹介を増やす構成へ／2026-10-18改定：フォロワー増加とエンゲージメント向上を目的とする「7人体制」へ）

## 0. このアカウントの目的
- Rapreは完全紹介制。新規のお客様は紹介のみで、Instagramに新規集客の役割は求めない。
- Instagramの目的は、フォロワーを増やし、エンゲージメント（保存・シェア・コメント）を増やすこと。
  紹介を受けた方がDMの前にアカウントを確かめたとき、信頼が確信に変わる状態をつくることが、その先にある役割。
- 見る数値は いいね ではなく、1投稿ごとの フォロー数、シェア÷リーチ、保存÷リーチ、リールの3秒視聴率と平均視聴時間。
- 制作の最初に「この投稿を、誰に送ってもらうか」（send_to）を1つ決め、1枚目（1コマ目）はその人の顔が浮かぶ一文にする。
  例：夕方に肩が上がっている同僚へ／子どもの寝かしつけの後に疲れ切っている友人へ。
  DMで送られる投稿は、送った人の評判を上げる投稿。送りたくなるかを常に問う。

## 0.5 7人体制（1回の実行の中で、次の順に工程として動く）
別々のセッションに分けない（受け渡しで文脈が切れ、品質が落ちるため）。各工程の合否基準を満たさなければ次へ進まない。
1. 編集長：担当枠・カテゴリー・send_to を決め、最後に全成果物を審査する（6. 検査）。ブランドの静けさと上品さに反するものは差し戻す。
2. サイエンスリサーチャー：根拠を、その回に実際に読んだ論文・公的情報だけで固める。表現規制（4. の禁止表現）と過去テーマとの重複を審査する。
3. コピーライター：キャプション、締めの4要素、検索キーワード（post.json の keyword）、line.txt を書く。
4. アートディレクター：カルーセルとストーリーズの文字量・改行・強調（<em>）を決め、書き出した画像を目で確認する。
5. リールディレクター：リールとトライアルリールのコマ構成と秒数を決め、最初の1秒で何の話か分かるようにする。
6. コミュニティマネージャー：ストーリーズ（新着のお知らせ／金曜の保存版リマインド）と line.txt の送る相手を決める。コメント返信はしない。
7. アナリスト：別の定期実行（毎週土曜の朝「Rapre Instagram 週次分析」）が担当する。制作の実行では数値の取得をしない。
   制作の実行は、最新の週報 automation/weekly-reports/ と automation/proposals.md を読み、状態が「採用」の提案だけを反映する。
   「提案中」「不採用」の提案は反映しない。

## 1. 投稿枠
- 月曜 20:00：通常投稿（カルーセル5枚）＋ストーリーズ（新着のお知らせ1枚）
- 木曜 20:00：リール（7〜12秒）＋ストーリーズ（新着のお知らせ1枚）
- 金曜 20:00：トライアルリール（7〜12秒。フォロワー以外に先に配信される形式）＋ストーリーズ（その週の月曜の投稿の保存版リマインド1枚）
- 担当の決め方：日曜の実行は翌日月曜の枠、水曜の実行は翌日木曜の枠、木曜の実行は翌日金曜の枠を担当する（Asia/Tokyo）。
- 1枠で同じ内容を複数の形式に重ねて出さない（初動の反応が分散するため）。
- 月曜・木曜のカテゴリーは次の順で1枠ごとに進める（6枠で1巡。state の next_index）:
  美肌 → 化粧品 → 姿勢 → 健康 → 食事 → カラダの不調
- 金曜のトライアルリールは、上の順番とは別の連載「40代のカラダ図鑑」。
  1本につき、40代女性のカラダやお肌の仕組みのファクト1つを、7〜10秒で伝える。
  テーマは state の log と discovery_log のどれとも科学的な切り口が重ならないこと。
- 投稿時刻は 2026-10-19 から4週間 20:00 で試し、その後に週報の結果で見直す。
- 進行状況と過去テーマは automation/rapre-state.json に記録する。

## 2. アカウント情報
- サロン名: Rapre（Wellness & Beauty）／運営: 株式会社エレメンタルトリニティ／東京都港区
- 理念: 関わるすべての人に感動を与える

- 独自技術: ボディチューニング（骨盤矯正・筋膜リリース・ストレッチ）
- 対象: 美容・健康意識の高い40代女性と、その方が投稿を送る相手
- 題材の参考: https://note.com/rapre_wellness と https://note.com/synca2025

## 3. テーマ選定
- 同じカテゴリーの過去テーマ（state の log、discovery_log と past_themes_before_automation）と科学的な切り口が重ならないこと。
- 候補を3つ以上出し、重複・根拠の弱さ・表現リスク・「人に送りたくなるか」の4観点で3回ふるいにかける。
- 根拠は皮膚生理学・筋肉生理学・栄養学の論文や公的機関の情報を、その回に実際に読んで確認できたものだけ使う。
  読めなかった資料、記憶だけの数値は使わない。確認できた根拠が無ければ、そのテーマは捨てる。
- 研究の限界（対象者、規模、関連か因果か）を根拠のスライド（またはコマ）とキャプションに明記する。
- 毎回、Instagramの最新のアルゴリズム情報を検索して確認し、この手順書と矛盾する変更があれば最終報告に書く（手順書は勝手に変えない）。

## 4. 文章の規則
- 「肌」は「お肌」、「体」は「カラダ」と表記する（「美肌」は例外）。強調の太字記号は使わない。
- 敬語（です・ます調）。上品で静かな語り口。煽らない。AIらしい決まり文句（「いかがでしたか」「〜の秘密」など）を避ける。
- 使ってはいけない表現: 治る、改善、効果がある、解消、必ず、絶対、痩せる、若返る などの断定や効能の保証。
  医療行為と誤認される表現、他社の誹謗、ビフォーアフターの保証、お客様の声の創作。
- 検索キーワード: 40代女性が実際に検索で使う言葉を1つ決め、post.json の keyword に書く。
  キャプションの書き出し（最初の80字以内）に、その言葉を自然に1回入れる。不自然な詰め込みはしない。
- キャプション本文は空白を除いて600字以上800字未満（ハッシュタグを除く）。
  構成: send_to の人の場面から書き出す（キーワード入り）→ 仕組み → 研究で報告されていること（限界つき）
  → Rapreの取り組みと自宅でできること → 締め（下の4要素）
- 締めの4要素（言い回しは毎回変える。直近4回と同じ文は使わない）:
  1. 問いかけ1つ。選択肢は付けず、読み手の日常の場面を問う（例：「あなたが肩の重さに気づくのは、1日のどの時間でしょうか。コメントでお聞かせください。」）。
     「全て返信します」「番号でコメント」は使わない（返信は代表本人が自分の言葉で行う）。
  2. 保存のすすめ。いつ見返すと役に立つかを具体的に書く。
  3. DMで送るすすめ。send_to の人を具体的に書く（例：「夕方になると肩が上がっている同僚がいたら、この投稿をDMで送ってあげてください。」）。
  4. フォローのすすめと紹介制の一文（言い回しは調整可）:
     「40代のカラダとお肌の仕組みを、毎週お届けしています。見逃したくない方は、フォローしてお待ちください。Rapreは完全紹介制のプライベートサロンです。」
- ハッシュタグは5個: テーマに合うタグ4個 ＋ 最後に #ボディチューニング。
  4個は投稿の主題を表す日本語のタグ（例：#猫背 #デスクワーク #40代美容 #港区エステ）。主題と無関係なタグは付けない。
  脱毛のタグは脱毛を扱う回だけ（その回は post.json に "hair_removal_topic": true）。
- 人物写真は使わない。

## 4.5 デザイン（2026-10-13改定：ゴールドとホワイト）
- 配色はゴールドとホワイト。1枚目（hook）と最後（cta）、ストーリーズはゴールド地に白文字、途中の枚は白地にゴールドのアクセント。
  白地の本文のみ読みやすさのため深い墨色。配色とレイアウトは tools/render.mjs が自動で付ける。手で色を指定しない。
- 1枚目（1コマ目）のタイトルは、いちばん刺さる言葉を1か所だけ <em>…</em> で囲む（ゴールド地では白の下線で強調される）。
- タイトルは短く。1枚目は3行以内、1行7字前後。
- 人物写真は使わない。

## 5. 生成
1. posts/rapre/<YYYY-MM-DD>_<英語の短い名前>/ を作り、post.json と caption.txt を書く。
   post.json の必須項目: brand（"RAPRE"）、format（月曜は "carousel"、木曜は "reel"、金曜は "trial_reel"）、send_to、keyword、category、slot、story。
   - carousel: slides 5枚（hook, text, evidence, text, cta）。型は posts/rapre/2026-10-19_posture/（ただし5枚目は下の新しい形）。
     5枚目（cta）は保存とフォローのカード: eyebrow "SAVE & FOLLOW"、title に send_to の人へ向けた一文、
     tags に「保存して見返す」「DMで送る」「フォローする」の3つ、sub に「40代のカラダとお肌の仕組みを<br>毎週お届けしています」。
   - reel / trial_reel: reel.frames に2〜4コマ、各コマに sec（秒）。合計は 7〜12 秒（クロスフェード0.4秒ずつ差し引き）。
     1コマ目は hook で、結論の一文を大きく（最初の1秒で何の話か分かること）。2コマ目に根拠1つ（evidence か text）、
     最後のコマは cta（eyebrow "SAVE & FOLLOW"、送る相手への一文、tags は上と同じ3つ、sub はフォローのすすめ）。
     各コマの文字は短く、1コマ3秒で読める量にする。
     trial_reel は category を "カラダ図鑑 / BODY NOTE" とし、フォロワー以外の方が初めて見る前提で、専門用語を避ける。
   - story:
     月曜・木曜は新着のお知らせ（eyebrow "NEW POST"、title は1枚目の一文、sub「新しい投稿を公開しました<br>プロフィールからご覧ください」）。
     金曜は保存版リマインド（eyebrow "SAVE"、title はその週の月曜のカルーセル1枚目の一文、
     sub「月曜の投稿を、保存版として<br>プロフィールからご覧ください」）。post.json に "reminder_of": "<月曜のフォルダ名>" を書く。
     その週の月曜の投稿が無い場合は、直近のカルーセルを使う。
2. `npm install` のあと `node tools/render.mjs posts/rapre/<フォルダ>` を実行する。
   「文字がはみ出しています」「リールの長さが」と出たら直して再実行する。
3. `node tools/check.mjs posts/rapre/<フォルダ>` を実行し、すべて合格にする。
4. 書き出した画像（カルーセル5枚、またはリールの全コマ）とストーリーズを実際に画像として見て、崩れや誤字が無いか確認する。
5. 月曜・木曜の枠は line.txt を書く（代表が公開後に、send_to に当てはまるお客様へLINEや個別DMで投稿と一緒に送る文）。
   1行目「送る相手の目安：〇〇のお客様」、続けて本文60〜160字。代表の一人称・敬語で、
   今回の内容の要点1つと「よろしければ、同じようにお困りのご友人にも転送してください」に当たる一文を入れる。
   通ってくださっているお客様のうちInstagramをフォローしているのは約3割（代表談、2026-10-13）。
   金曜のトライアルリールはフォロワー以外の方に向けたものなので、line.txt は作らない。

## 6. 検査（編集長の工程。1つでも不合格なら予約しない）
- tools/check.mjs がすべて合格。
- スライドの記述が、その回に確認した根拠と一致していること。
- 1枚目（1コマ目）が send_to の人に向いた一文になっていること。
- 不合格を直せない場合は予約せず、理由を最終報告に書いて終了する。誤った内容を公開するより1回休む方がよい。

## 7. 保存と予約
1. `git pull --rebase` のあと、main に commit して push する（週次分析の実行も同じリポジトリに書くため）。
2. 画像と動画の公開URLは
   https://raw.githubusercontent.com/rapre-mita0105/rapre-media/main/posts/rapre/<フォルダ>/...
   取得できること（HTTP 200）を確認する。
3. Metricool（ブランドID 7099534、タイムゾーン Asia/Tokyo）に同時刻で2件予約する。
   - 月曜: 通常投稿 instagramData.type=POST、media=carousel/slide_01〜05.jpg、text=caption.txt 全文
   - 木曜: リール type=REEL、media=reel/reel.mp4、videoThumbnailUrl=reel/cover.jpg、text=caption.txt 全文
   - 金曜: トライアルリール type=TRIAL_REEL、media=reel/reel.mp4、videoThumbnailUrl=reel/cover.jpg、text=caption.txt 全文
   - 3日とも: ストーリーズ type=STORY、media=story/story.jpg、text は送らない
   すべて autoPublish=true。同じ枠に既に予約がある場合は重複して作らない。下書き（draft）の予約は数えない。
4. 予約を読み戻して2件あることを確認する。
5. 月曜・木曜の枠は、最終報告の最後に line.txt の全文をそのまま載せる（代表が公開後にコピーして使う）。
6. automation/rapre-state.json を更新して push する。
   - 月曜・木曜：next_index と next_slot を進め、log に日付・形式・カテゴリー・テーマ・send_to・keyword・根拠を追記する。
   - 金曜：next_trial_slot を1週進め、discovery_log に日付・テーマ・send_to・keyword・根拠を追記する。

## 8. 振り返り
- 数値の取得と分析は、週次分析の実行（アナリスト）が行い、automation/weekly-reports/<日付>.md と state の metrics に書く。
- 制作の実行は、最新の週報を読み、最終報告に直近の数値を2〜3行で引用する。数値を自分で取得し直さない。
- 紹介の数（紹介でのお問い合わせ・ご来店）はInstagramの数値では取れない。代表から伝えられた分だけ state の referrals に記録し、推測で書かない。
- 手順書の変更は代表の判断で行う。週次分析の提案は automation/proposals.md に書かれ、代表が「採用」と伝えたものだけが反映される。

## 9. 対象外（代表本人が行う）
- コメントへの返信。自動では返信しない。
- line.txt のお客様への送付。
- ストーリーズの投票・質問スタンプ（Metricoolの予約項目に無いため）、協力者とのコラボ投稿、代表本人の一人称の投稿。
- トライアルリールの、フォロワーへの公開の判断（Instagramアプリ上で行う）。
